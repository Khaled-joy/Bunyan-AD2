# REPLIT AGENT BUILD PROMPT — Bunyan: Game Library, Progress & Store

Build three pages for the Bunyan platform (بنيان أبوظبي). Everything must be bilingual EN/AR with full RTL/LTR switching, using the existing dark Emirati theme (#0B0F1A background, #F5F5F0 text, #C9A227 gold accent, brand red/yellow/teal/blue, Tajawal/Cairo fonts, Al Sadu geometric pattern accents). All content lives in JSON. Adding a game, a skin, or an event must require **zero code changes**.

## PART 1 — GAME LIBRARY PAGE (`/library`)

### Structure

Two top-level categories rendered as tabs (or stacked sections on mobile):

**1. Default Games — الألعاب الأساسية**
Always available. Never expire. Playable by all cycles that match the game's cycle tags.

**2. Event Games — ألعاب الفعاليات**
Time-limited games built in collaboration with partner entities (Zayed University, MBZUAI, DMT, and others). Each event game has its own unique trophy and captures something no default game captures. When the event window closes the game becomes permanently locked and unplayable, but the page still shows it in an archived state with its trophy.

## PART 2 — PROGRESS PAGE (`/progress`)

Private to the signed-in player. No comparison to other children anywhere on this page — no rankings, no percentiles, no "you're behind" language. Use "Not yet / لم تكتمل بعد" for anything incomplete.

### Section A — Summary strip
Total coins, games played, trophies earned, current streak (days played). Four stat cards, gold accent.

### Section B — Play history
Reverse-chronological list of every session, paginated (20 per page), from the `sessions` table:

| Column | Note |
|---|---|
| Game | thumbnail + title, links to library detail |
| Date & time | localised, Arabic numerals in AR mode |
| Duration | mm:ss |
| Result | levels completed / total, plus an accuracy band label (Growing / Solid / Strong) — **never a raw percentage or a fail label** |
| Coins earned | with coin icon |
| Trophy | trophy icon if one was earned in that session |

Filter by game and by date range. Empty state: "Your journey starts with your first game / رحلتك تبدأ بلعبتك الأولى" + link to library.

### Section C — Per-game progress
One row per game the player has access to:
- Progress bar: levels completed / total
- Best run label
- Coins earned from this game to date
- "Not yet started" state for untouched games with a Play link
- Ended event games appear here too, frozen at whatever the player reached, with an "Archived" chip

### Section D — Trophies & rewards
Grid of all trophies. Earned = full colour + date earned. Unearned = silhouette + a single clear unlock line ("Complete Turathuna Gold three times"). Trophies from ended events stay permanently visible and permanently unobtainable if not earned — label them "Event closed" rather than anything discouraging.

### Section E — Rewards tracker
For each unlockable store item the player is close to: item art, price in coins, current balance, progress bar, and "X coins to go / باقي X عملة". Show the 3 nearest items only. Tapping one deep-links to that item in the store.

### Section F — Masar profile (six components)
Six radial progress rings: Core Life Skills, Cognitive, Practical, Personal Growth, Social Cohesion, Transformative.

**Respect confidence gating.** If a component has not reached the two-game coverage threshold, do not display a value. Render the ring in a neutral outline with the label "Building your profile / جارٍ بناء ملفك" and a tooltip explaining that more games across different types are needed. Never show a low-confidence number to a child.

## PART 3 — COINS

Single currency: **Coins — عملات**. If the codebase already uses Sparks/شرارات, rename it to Coins everywhere — do **not** introduce a second currency.

### Award rules (server-authoritative)
On session completion, the server computes and writes to a `coin_ledger` table:

- **Completion award**: game's `coinReward.completion`
- **Performance bonus**: 0 to `coinReward.bonusMax`, scaled by accuracy band
- **First-play-of-day bonus**: +10, once per game per day
- **Daily cap**: 150 coins per player per day. Once hit, further sessions award 0 and the results screen shows "Daily coins reached — come back tomorrow! / وصلت للحد اليومي — نراك غداً" with no negative framing
- **No coins** are awarded for levels where a booster was active, and no coins for assessed levels

Coins are **never computed on the client**. The client only displays what the ledger returns. The ledger is append-only: every row records `player_id`, `session_id`, `game_id`, `amount`, `reason`, `created_at`. Spending writes negative rows. Balance = `SUM(amount)`.

### Results screen
After every game, before returning to the library: animated coin counter counting up, a breakdown line for each award component, new trophy reveal if earned, updated total balance, and two buttons — **Play again** and **Back to library**.

## DATA MODEL (Postgres)

```
sessions        (id, player_id, game_id, started_at, ended_at, duration_ms,
                 levels_completed, levels_total, accuracy_band, trophy_id)
coin_ledger     (id, player_id, session_id, game_id, amount, reason, created_at)
inventory       (id, player_id, item_id, acquired_at, source)   -- source: purchase | reward
equipped        (player_id, slot, item_id)
trophies_earned (id, player_id, trophy_id, game_id, earned_at)
```

All balance, purchase and award logic runs server-side. The client never sends a coin amount.
